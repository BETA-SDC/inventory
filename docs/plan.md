# SDC 物资管理实施规划

规划日期：2026-10-10。仓库公开，初期物资较少，后期需要扩展。对象包括公共设备、工具、办公耗材和食品饮料。

## 当前进度

第一阶段完成。第二阶段已实现七类表单解析、缺漏提示、只读 Issue 拉取、管理员本地草稿、申请及台账变更检测和整组操作校验后登记。新增入库、异常及盘点的实际处置仍由管理员明确填写；暂未实现自动评论、状态标签、并发队列、包装换算和保存条件匹配。

第三阶段已实现稳定对象／货位档案、预填申请链接、A4 二维码标签 PDF，以及只读提醒报告和每周报告 Workflow；特殊标签纸适配、Issue 自动提醒尚未实现。真实管理员、位置及物资仍待录入。工具只是管理员辅助，GitHub 权限配置由仓库所有者维护。

## 已确认的边界

- 全体 SDC 成员使用 GitHub，通过 Issue 提交申请。
- 预计三至四名管理员，均可审核和登记；每件申请由一名管理员负责，避免重复处理。
- 普通成员不修改文件、不提交 PR。管理员使用工具生成文件并提交。
- 原则上先申请、批准后领取；特殊情况允许补登记，并记录实际时间和原因。
- 每次食品和耗材领取均提交 Issue，不使用定期汇总代替。
- 成员归还后报告位置、时间和实物状况；管理员定期检查，检查通过后确认归还。
- 仓库公开，但手机号等信息遵循组织既有私有仓库规范。
- 尚未确定实际存放地址和管理员名单，不编造；上线前登记。

## 两部分

公开 Issue 是申请、讨论、审核和交接入口。正式文件是管理员确认后的档案与业务记录。申请正文可以修改，但不能因此直接修改已经入账的事实。

管理员通过登记工具维护单一数据来源；工具生成查询页面和标签。Git 历史用于追溯文件修改，不替代业务流水。

## 信息模型

| 对象 | 唯一编号 | 核心信息 |
| --- | --- | --- |
| 物品定义 | `ITM-000001` | 名称、类型、分类、型号、基本单位、储存条件 |
| 位置 | `LOC-000001` | 名称、上级位置、定位说明、是否可用于存放、保存条件 |
| 实物对象 | `AST-000001` / `BAT-000001` | 物品引用；资产序列号或批次、到期日期 |
| 实际操作 | `EVT-000001` | 类型、对象、数量、来源、去向、时间、申请、审核人、借出关联 |
| 盘点 | `STK-000001` | 范围、快照、实测、差异、复核及关联调整记录 |

资产逐件管理，一个资产数量为一；食品与耗材按批次管理。物品、资产和批次编号均永久不变，不编码位置或负责人。批次可以在多个货位存放，库存按“对象 + 位置”计算。

所有数量使用目录规定的整数基本单位，例如瓶、包、张；箱等包装按已登记的换算规则转成基本单位。散装称重以后使用克等整数单位，不使用浮点近似数量。

```text

stocktakes/2026/STK-000001/       盘点任务
attachments/objects/             可公开附件
views/                           自动查询视图
templates/                       管理员填写模板、标签模板
scripts/                         校验、登记、查询与标签工具
tests/                           库存、借还与错误处理测试
```

首阶段脚本递归读取这些目录，允许按上面结构增长。当前不因搬家、人员变动、状态变化或耗尽而移动档案。查询维度从字段生成，不建立互相重复的台账。

## Issue 类型

| 类型 | 前缀 | 完成条件 |
| --- | --- | --- |
| 新增或入库 | `[intake]` | 验收、编号、贴标、登记完成 |
| 借用 | `[borrow]` | 所有借出对象归还通过检查或异常处置完毕 |
| 归还 | `[return]` | 管理员检查并登记 |
| 领用或消耗 | `[consume]` | 实际交付或消耗并登记 |
| 调拨 | `[transfer]` | 实际移交并登记来源、目标位置 |
| 异常 | `[incident]` | 核实、维修或处置、登记完成 |
| 盘点或纠错 | `[stocktake]` | 复核差异并登记调整 |

父借用 Issue 保持打开，分批归还和异常处理作为子 Issue。普通成员填写原申请编号，管理员负责建立 Sub-issue 关系。盘点可拆出按货位检查的子 Issue。简单领用不强制拆分。

## 权限与审核

公开仓库允许外部账号提交 Issue，但业务申请只处理已核实的 SDC 成员。管理员在私有信息或组织成员记录中核实身份，不能仅凭申请人自行勾选身份确认。

成员不授予仓库写权限。正式文件修改限管理员；仓库所有者在启用时确认成员权限、管理员权限及保护规则。管理员名单通过 `catalogs/administrators.json` 维护，初始为空。

申请状态采用 `status:pending`、`status:needs-info`、`status:approved`、`status:active`、`status:awaiting-check`、`status:completed`、`status:rejected`、`status:cancelled`。同时只保留一个状态标签。业务类型由独立 `type:*` 标签表示。

批准不扣库存。实际交付时记账；借用资产仍属于 SDC，只改变去向和责任人。归还待检查时仍未结清借用，也不能再次借出。损毁先标记待处置，维修、报废、遗失等最终结果单独登记。

## 私有信息

沿用 `community/docs/procedures/privacy/private-information-reference.zh.md` 与 `community-private-information/guides/contact-maintenance.zh.md`。

成员先维护已有的稳定联系人条目；公开申请只贴普通引用链接，不复制手机号、私有姓名或其他敏感上下文。无私有仓库权限者联系管理员办理。公开资料本身完整可读。

不使用 Markdown 折叠、HTML 注释或掩码作为秘密提交渠道。标签只印物资信息和公开档案地址，不印联系方式、借用人或私有地址。敏感位置仅提供公开可用的位置代码，具体访问说明放私有仓库。

## 自动化阶段

### 第一阶段：基础与规则

- 完成规划、制度、七类申请表单和管理员填写模板。
- 管理员工具分配编号、校验关联和数量，登记实际业务记录。
- 从正式记录生成库存、资产和未结借用台账。
- CI 校验文件及测试，只有读取权限。
- 真实管理员、位置与物资由管理员上线时登记。

### 第二阶段：Issue 到登记草稿

- 自动解析七类表单，反馈缺漏，不自动批准或写入文件。
- 管理员工具按 Issue 编号拉取申请，展示身份核实、库存和未结借用情况。
- 生成管理员可审阅的登记草稿；管理员确认实际操作、时间、数量后落盘。
- 记录审核时的内容摘要；审核后关键字段修改需要重新确认。
- 检查重复入账、多人并发、批次优先到期、保存条件与单位换算。
- Issue 评论和标签回写只在上线配置并授权后启用。

### 第三阶段：标签与提醒

- 生成资产、批次、货位标签，默认 A4 排版，保留可读编号和二维码。
- 标签链接到稳定公开档案入口，扫码后进入相应申请模板。
- 食品标签标明批次与到期日期；资产永久标签不印可变存放地址。
- 输出待检查归还、逾期借用、食品临期和待处置物品清单。
- 每周生成只读提醒报告作为 Actions artifact；报告不修改 Issue 或正式台账。
- 管理员定期检查归还，默认每周一次；紧急归还可提前检查。
- 提醒聚合到管理入口，只对新增或变化事项通知，避免重复刷屏。

### 第四阶段：盘点与运营

- 从指定位置生成盘点快照；盘点期间新增业务不能被旧快照覆盖。
- 导入实测结果，生成差异清单，管理员复核后追加调整记录。
- 资产使用与损耗统计、备份和恢复演练。

## 一致性要求

- 每次业务使用唯一操作编号；一期按“仓库 Issue 编号 + 本次操作键”防重复，支持一个申请分批完成。
- 编号从既有文件推算；本地工具不支持并发写。多管理员登记前拉取最新主分支，提交前检查，非快进推送时重新拉取并重算，不能强推。
- 后续集中工具采用串行队列分配编号与记账，不能让各管理员分别分配同一个编号。
- 业务记录追加保存；纠错通过管理员说明和补偿操作，不静默改写历史。
- 批次库存不得负数；同一资产不能同时借给两人；归还数量不得超过原借出数量。
- 工具不把 Issue 文本拼成 shell，不信任用户提供的文件路径。
- 私有资料不进入公开 Actions 日志、查询结果或生成产物。

## 验收与启用

先使用测试数据覆盖完整入库、借出、部分归还、归还检查、消耗和调拨；再使用真实少量物资试运行。

基础验收检查重复编号、负库存、重复记账、超额归还、失效引用与循环位置。后续集成验收覆盖公开外部申请、非管理员触发、申请修改、并发登记、标签扫描和盘点期间业务。

启用前由管理员完成：名单登记、位置登记、私有联系人核对、初始实物盘点、权限配置、贴标。未完成自动化不得在 README 宣称已经提供。
