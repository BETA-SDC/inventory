# 申请、审核与登记规则

## 成员

每次新增、借用、归还、领用、调拨或异常报告都提交对应 Issue。原则上先申请、批准后领取。特殊情况补登记时选择“补登记”，说明实际操作时间、原因和知情管理员，不把补登记当作默认领取方式。

借用必填预计归还日期。延期在原借用 Issue 申请，管理员确认后记录新期限；没有确认不视为延期成功。食品、纸张等无需归还的物品使用消耗申请。

归还提交单独 Issue，引用原借用编号，填写实际归还位置、时间、对象和数量，并提供可公开的状况说明或照片。不因自行关闭 Issue 而认定归还完成。

## 管理员

1. 一名管理员认领申请，核实成员身份与私有联系方式。
2. 检查对象、位置、数量、用途、日期和关联申请；信息不足要求补充。
3. 批准或拒绝，说明结果。批准不代表实物已交付。
4. 核实实际收货、领取或移交，使用登记工具生成记录并提交。
5. 在申请中记录实际数量、时间、台账提交及后续事项。
6. 符合完成条件后关闭；借用须等全部归还或异常处理完成。

归还检查默认每周一次。未检查的对象不恢复可借用；管理员记录实物位置及状况后才登记 `return`。损毁对象先通过 `hold` 隔离，不能再次领取；后续以解除隔离、消耗或异常处置记录处理。

拒绝、取消或未执行申请不产生库存流水。已经执行后撤销申请不能删除流水，必须核实后追加纠正记录。

## 父子申请

```text
[borrow] 活动投影仪借用
  [return] 活动投影仪借用 - 归还 AST-000001
  [incident] 活动投影仪借用 - 配件损毁
```

成员在表单填写原借用 Issue 编号，管理员添加父子关系。一次借用的多件资产可以分批归还；父 Issue 中列出未结对象。异常子 Issue 关闭不等于资产已归还，管理员必须确认最终去向。

## 食品

领取时标明批次、数量和单位。优先使用先到期的可用批次；过期食品不按正常领用处理。不能确认到期日期的食品先待核实，不直接投入可领用库存。预包装食品记录标签上的到期日期；特殊食品由管理员确认适用的保存要求。

## 实际业务记录

记录操作编号、类型、对象、整数基本单位数量、来源位置、目标位置或借用人、发生时间、申请编号、操作键和登记管理员。归还引用原借出操作编号。数量和当前状态由这些记录计算，不能直接修改生成表。

事件类型：`receive`、`loan`、`return`、`consume`、`transfer`、`hold`、`release`、`writeoff`、`adjust-in`、`adjust-out`。一期对损毁借用资产的核销和借用延期只保留人工审核入口，完整自动处置在第二阶段实现，不能伪造归还替代。
